# Resume Classification and Job Role Recommendation using NLP and BiLSTM

## 📌 Overview

Have you ever looked at a job description and wondered, **"Is this role actually a good match for my skills?"**

Finding suitable job roles can be difficult when a resume contains a wide range of skills and experiences.

This project aims to make that process easier by analyzing a user's resume and recommending the **Top 5 job roles** that best match their profile.

The system uses **Natural Language Processing (NLP), custom Word2Vec embeddings, and a Bidirectional LSTM (BiLSTM)** model to classify resumes into different job categories and generate ranked job-role recommendations.

---

## 🎯 Objective

The main objectives of this project are to:

- Analyze resume text using NLP techniques
- Convert resume text into numerical representations
- Learn domain-specific word embeddings using Word2Vec
- Classify resumes into relevant job categories
- Provide the Top 5 most likely job-role recommendations
- Help job seekers identify suitable career opportunities more easily

---

The dataset contains resume text along with its corresponding job category.

### Dataset Statistics

## 🧹 Text Preprocessing

The resume text is cleaned before being passed to the model.

The preprocessing steps include:

- Converting text to lowercase
- Removing URLs
- Handling new lines and tabs
- Removing unnecessary characters
- Normalizing whitespace
- Removing the initial resume header based on the dataset format

The goal is to create cleaner and more consistent text for the NLP pipeline.

---

## 🔢 Label Encoding

The job categories are categorical text labels.

For model training, these categories are converted into numerical class labels using **LabelEncoder**.

For example:

```text
Python Developer → Numerical Label
Java Developer   → Numerical Label
...
```

This allows the neural network to work with the target classes.

---

## ✂️ Train-Test Split

The dataset is divided into:

- **80% Training Data**
- **20% Testing Data**

A fixed `random_state=809` is used to make the split reproducible.

The training data is used to learn patterns from resumes, while the test data is reserved for evaluating the model on unseen resumes.

---

## 🔤 Tokenization

The cleaned resumes are converted into sequences of integer IDs using the Keras `Tokenizer`.

Configuration:

```python
Tokenizer(
    num_words=1000,
    oov_token="<OOV>"
)
```

The tokenizer assigns an integer index to each word.

For example:

```text
python → 1
developer → 2
machine → 3
learning → 4
```

The `<OOV>` token is used to represent words that are outside the selected vocabulary.

---

## 📏 Sequence Padding

Resumes can have different lengths, but the neural network requires inputs with a consistent shape.

Therefore, all sequences are padded or truncated to a maximum length of **500 tokens**.

Configuration:

```python
maxlen = 500
padding = "pre"
truncating = "post"
```

This ensures that every resume has the same input shape:

```text
(500,)
```

---

## 🧠 Custom Word2Vec Embeddings

Instead of representing words only using integer IDs, this project uses a **custom Word2Vec model trained on the resume dataset**.

### Word2Vec Configuration

```text
Vector Size: 100
Window: 10
Minimum Count: 2
Workers: 4
```

Each word is represented as a **100-dimensional vector**.

For example:

```text
python → [0.12, -0.34, 0.56, ..., 0.21]
```

### Why Word2Vec?

Word2Vec learns relationships between words based on their surrounding context.

Since the model is trained specifically on resume data, it can learn representations related to the terminology and patterns found in the job domain.

---

## 🧩 Embedding Matrix

The Word2Vec vectors are mapped to the word indices generated by the Keras tokenizer.

The embedding matrix has the shape:

```text
20,000 × 100
```

Each row corresponds to a tokenizer word index, while each row contains the corresponding 100-dimensional Word2Vec representation when available.

This matrix is then used to initialize the model's Embedding layer.

---

## 🤖 Model Architecture

The classification model uses a **Bidirectional LSTM**.

```text
Input
  ↓
Embedding Layer
  ↓
Bidirectional LSTM (128)
  ↓
Dropout (0.3)
  ↓
Dense (32, ReLU)
  ↓
Dropout (0.3)
  ↓
Dense (10, Softmax)
```

### Model Configuration

| Layer | Configuration |
|---|---|
| Input | 500 tokens |
| Embedding | 20,000 × 100 |
| BiLSTM | 128 units |
| Dropout | 0.3 |
| Dense | 32 neurons |
| Activation | ReLU |
| Output | 10 neurons |
| Output Activation | Softmax |

The model contains approximately **2.24 million trainable parameters**.

---

## 🔄 Why Bidirectional LSTM?

LSTM is useful for processing sequential text and learning patterns across a sequence.

A Bidirectional LSTM processes the resume in both directions:

```text
Forward:     Beginning → End
Backward:    End → Beginning
```

This allows the model to capture contextual information from both sides of the sequence.

This is useful for resumes because the meaning and relevance of words can depend on their surrounding context.

---

## 🎯 Classification

The final layer contains **10 neurons**, corresponding to the 10 job categories.

Softmax converts the model's outputs into probabilities.

For example, a resume might produce:

```text
1. Python Developer       → 95.50%
2. Project Manager         → 1.24%
3. Database Administrator  → 1.00%
4. Java Developer          → 0.96%
5. Web Developer           → 0.67%
```

The probabilities are then sorted to generate the **Top 5 job recommendations**.

---

## ⚙️ Model Training

The model was trained using:

```text
Optimizer: Adam
Loss: Sparse Categorical Crossentropy
Metric: Accuracy
Maximum Epochs: 100
Batch Size: 256
Validation Split: 20%
```

### Early Stopping

Early stopping was used with:

```text
Monitor: Validation Loss
Patience: 3
Restore Best Weights: True
```

This helps prevent unnecessary training and reduces the risk of overfitting.
